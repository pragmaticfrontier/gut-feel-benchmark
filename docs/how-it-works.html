This page describes version 0.1 as of 17 October 2026

Gut Feel Benchmark

The Gut Feel Benchmark asks a model for one probability about a situation an expert would judge at a glance. It scores that number against the truth, then scores it again at seven deadlines from a quarter of a second to 16 seconds, and an answer that misses a deadline earns nothing there.

Every answer passes through one function, AI SDK 7's experimental_decide, whether the contestant is a decision model such as TypeSafe AI's Jev or a chat model such as Claude Opus 5.5. That shared path is what lets one table rank both kinds of model.

One request, one number back

Every item is a Jev request with two parts. The state describes the situation, and the question is one statement that is either true or false. The contestant returns the probability that the statement is true, and that number is all the benchmark scores.

Decision models answer the request as it stands. src/bench.ts hands it to experimental_decide, which sends it through Vercel AI Gateway to Jev, Microsoft-Decision-1 or OpenAI's Decisions API, and each one returns a probability without writing any text.

Chat models answer in text, so they need an adapter. src/llm-decision-model.ts turns the same request into a system message and a prompt, asks for structured output that holds one number, and switches reasoning off unless the spec names an effort level. From file to report

The command npm run bench -- --limit 25 takes every contestant through the same five steps, one contestant after another.

  1. Load the items

    The runner takes the first 25 items of each pack, 100 in all. Without --limit it takes all 703.

  2. Warm the connection

    The runner first times five Gateway requests that do no model work and saves the median as the network floor. Each contestant then answers one item untimed, so the first scored call does not carry the TLS handshake.

  3. Ask four at a time

    Four requests run at once. Each is cancelled after 120 seconds and retries are off, so a slow or failed call is recorded as it happened.

    decide: specs

    typesafe-ai/jev goes to Gateway as a decision model, and the probability comes back as a number.

    llm: specs

    anthropic/claude-opus-5.5 goes through the adapter, which calls generateText with structured output, and the number comes back inside JSON.

  4. Record each answer

    Each answer is appended to results/2026-10-17/predictions.jsonl as soon as it returns, with the probability, the wall-clock latency, the token counts and any error. Chat-model answers also carry their reasoning tokens and any SDK warnings.

  5. Score and write the report

    src/score.ts scores each pack, and src/report.ts writes report.md and summary.json, pricing each contestant from Gateway's public price list.

Runs resume. A second run with the same name skips every answered item and retries the failures, so an interrupted run loses only the calls that were in flight.

Four packs, two kinds of truth

Two packs score a forecast against an exact probability, and two score it against what happened. An exact truth takes luck out of the score. A forecast of 0.70 for a hand with 0.72 equity is scored against 0.72, whoever would have won the one showdown.

Both exact packs hold 10 items in each tenth of the probability range. Random deals would leave the ends almost empty, because 84% of them land between 30% and 70% equity and fewer than 4% fall below 20% or above 80%. Stratifying puts long shots and near-locks in the test.

The two outcome packs test judgement on real cases, and each covers a weakness of the other. The Cleveland heart data has been public since 1988, so a model may remember it, and the report scores it in full but keeps it out of the headline Gut Score and Skill. The Hacker News stories were posted 2 to 9 October 2026, a week or two before any model meets them. Only 4.0% of the 6,889 stories posted that week reached 100 points, so the pack raises the share to 25% and says so in the question, which judges a model on telling hits from misses and not on guessing the rate.

Skill is the share of error a forecast removes

Skill is the Brier skill score against the pack's base rate. It compares the forecast's squared error with the squared error of a forecaster who answers the base rate every time.

skill = 1 − mean((q − t)²) / mean((b − t)²)
q
the forecast, from 0 to 1
t
the truth, an outcome of 0 or 1 or an exact probability
b
the base rate, the mean truth over the pack's scored items

A perfect forecast scores 1. Answering the base rate scores 0, and any other constant answer scores below 0, so a model gains nothing by saying 50% to every hand. A negative score means the model did worse than the base rate would have.

The ends of the range are where skill is earned. On the poker pack the base rate is 0.499, and for the 4♣ 10♣ hand, with exact equity 0.411, the base rate's squared error is 0.0077. On a 0.936 hand such as A♠ A♥ against 8♠ A♣ it is 0.19, twenty-five times as much. The score sums errors over all 100 hands before dividing, so a model that prices near-locks and long shots well removes most of the error there is to remove.

The benchmark scores a probability as a probability. Accuracy at 0.5 would give the same credit for 0.51 and 0.99 on a hand that wins 93.6% of the time, and the report keeps accuracy only as a secondary column.

The Gut Score counts skill that arrives in time

The Gut Score rescores each pack at seven deadlines, 0.25, 0.5, 1, 2, 4, 8 and 16 seconds, with every answer slower than the deadline replaced by the base rate. It averages the seven skills, multiplies by 100 and then averages across the three headline packs. No deadline scores above the skill of every answer, so a late answer can lower a score but never raise it.

Answers at 1.2 s beat 4 of the 7 deadlines, so this forecaster keeps its skill of 0.60 at four of them and scores 0 at the other three, for a Gut Score of 34.3.

The scale prices speed steeply on purpose. A perfect forecaster that takes 3 seconds scores 42.9, and so does a forecaster with half the skill that answers in 0.3 seconds.

The widget assumes every answer takes the same time. Real latencies vary from call to call, so the report rescores each deadline from each answer's own latency, and it prints raw skill beside the Gut Score so that a slow, accurate model stays visible.

Each chat model runs twice, with reasoning off and with high reasoning, which isolates the trade the benchmark exists to measure. Reasoning tokens bill as output, so the high-reasoning entry costs more per answer and answers later, and the three of them run last.

A human: spec puts a person in the same table. The runner prints each item exactly as a chat model sees it, takes a percentage from 0 to 100 and times the answer from the moment the item appears, so npm run bench -- --models human:alex --packs poker-equity --limit 25 records a poker player against the same 25 hands the models answered.

First results

The first live run, on 17 October 2026, put 25 items from each pack to seven contestants. The decision models win on the clock and the chat models win on judgement.

Claude Opus 5.5 with reasoning off has the highest skill in the field, 71.2, but its median answer takes 2.0 seconds, so it scores nothing at the three shortest deadlines and 32.0 overall. OpenAI's Decisions API reaches 65.1 in 0.30 seconds and leads with 59.0, and Jev is second at 51.3, ahead of Microsoft-Decision-1 in 99% of resamples.

More reasoning bought no skill. With high reasoning, Opus used 141 reasoning tokens per answer instead of 36, scored 69.9 against 71.2 and slowed from 2.0 to 3.1 seconds. The reasoning-off setting held for no chat model: GPT-6.1 Sol used 162 reasoning tokens per answer and Gemini 3.8 Flash 2,169, and Gemini thought past the 120-second limit on 23 of 25 poker hands.

The exact packs separate the field and the outcome packs barely do. Every chat model and the Decisions API scored 100.0 on the base-rate problems, while on the Hacker News pack no contestant passed a skill of 14.7.

Limits of version 0.1

The first run used 25 items per pack, so its intervals are wide, and GPT-6.1 Sol and Gemini 3.8 Flash with high reasoning have not run yet. Four gaps remain in the method itself.

  • The bootstrap resamples items, so the intervals cover which items were drawn but not run-to-run variation in a model's answers or latency.
  • The network floor shows how much of each latency is network, but latencies from two machines are still not comparable.
  • The report shows when a provider ignores the request to switch reasoning off, but the runner cannot force it off.
  • No human expert has answered a pack yet, although a human: contestant can.
